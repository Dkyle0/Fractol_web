# Fractol Web — инструкции для разработки

## Рабочие правила

- Общаться и писать интерфейс на русском. Это самостоятельный **Vue 3 + TypeScript + Vuetify + Pinia + Vite** проект. Не переносить Vue2-соглашения из других проектов.
- Приоритеты: корректность вычислений, плавность, понятный доступный интерфейс. Использовать закреплённые зависимости, не обновлять их попутно.
- Собственный код — MIT (Dkyle); сторонние лицензии сохраняются отдельно. `scripts/licenses.mjs` обновляет npm-уведомления и общий указатель, не перезаписывает текст SoftFloat. CI проверяет unit/tools/build, GPU-приёмку не заменяет.
- Текущее устройство и команды: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md); поведение пользователя: [docs/USER_GUIDE.md](docs/USER_GUIDE.md).
- Если есть корневой CLAUDE.md, учитывать его. Архивная история не является обязательной зависимостью разработки.
- Принятые решения добавлять в локальный `.local/project/DECISIONS.md` со стабильным ID, датой, статусом и последствиями; если файла нет — создать его. Актуальное публичное поведение отражать в руководствах. Не публиковать внутренние протоколы/артефакты в Git.

## Границы и данные

- `domain/` — чистый TypeScript без Vue/Pinia/WebGL; `rendering/` — без Vue/Pinia. Компоненты меняют сцену командами store и вызывают RenderSession, не внутренности WebGLBackend. Диагностический адаптер предназначен для тестов.
- GPU-ресурсы, программы, запросы и сырые массивы не помещать в глубокую реактивность. Освобождать ресурсы/подписки при завершении и учитывать поколение контекста перед async-доступом.
- Сохранять `SceneState.schemaVersion=1`, `formulaVersion=1`, `Library.version=1`, идентификаторы/даты сохранений и старые ссылки. Новые параметры нормализовать по формуле, неправильные внешние данные отклонять.
- Оформление, ресурсы, качество и панели не входят в сцену/ссылку/историю. Без ссылки открывается Mandelbrot/«Аврора», последняя камера не восстанавливается. История — 100 действий, группировка жестов/ползунков и 300 мс для серии навигации; поля фиксируются Enter/blur.
- Коллекция — 100 сцен, импорт до 1 МиБ, предварительный просмотр и объединение без дубликатов. Не терять доступные данные в памяти при ошибке localStorage.

## Рендеринг

- Два прохода: поле, затем цвет. Палитра/сдвиг/плотность не повторяют математику. Общая math identity — `domain/sceneIdentity.ts`; цвет исключён. Перед заменяющим preview инвалидировать завершённый ключ.
- Явный `julia-pointer`: один in-flight + последний ожидающий снимок только juliaRe/juliaIm, публикация целым кадром; старый снимок показывается как предыдущий, не готовность текущего. Через150мс покоя однократная отмена несовпадающего задания и финальный размер. Другие изменения сохраняют обычную отмену.
- При входе в pointer-series незавершённый обычный progressive job отменяется один раз; он не должен публиковать тайлы внутри атомарной серии. Последующий ввод не возвращает отмену каждого задания.
- GPU-кэш просмотра: неизменяемые завершённые итоговые RGBA8-поля, LRU32/4МиБ и8/4записей standard/economy, включая pending copies. Ключ math+арифметика/версия/кодирование+размер без цвета. Hidden/context loss/dispose очищают; allocation failure отключает заполнение до restore. Кэш PNG отдельно.
- Метрики v6 — уникальные события, фактические монотонные границы/счётчики обоих краёв; поле/тайл/отправка/кэш раздельно. Fence и отправки не физические кадры; не выдумывать времена для batch-событий. GPU-query drain≤500мс вне окна, cache bypass бенчмарка. `setNavigationFeatures` только диагностический A/B, не UI-предпочтение.
- Atomic-float обязан собирать готовые query во время работы, иначе32слота заполняются прогревом. Опрос неблокирующий; Vue-снимки при вводе ограничены250мс, полный поток событий от этого ограничения не зависит.
- Обычный просмотр: float32 до 2000 при допустимых координатах, иначе DS. Выбранный N сохраняется в движении; через 150 мс восстанавливается только разрешение. Редактор 64–2000, данные старых сцен 64–16384 без автоматического обрезания.
- Economy: только float32, `min(N,512)` постоянно, до 30 Гц, DPR ≤ 1 / ≤ 600 000 пикселей и без blur. Auto использует мобильные признаки при запуске, ширина/resize не переключают режим. Ручное предпочтение стекла сохраняется.
- Обычные пределы: DPR ≤ 1,5 и ≤ 3 000 000 пикселей. Профили auto/performance/quality управляют разрешением внутри текущих ограничений ресурсов. Готовый неподвижный экран не перерисовывается; скрытие вкладки отменяет работу и запрещает предъявления из продолжающейся подготовки программ.
- DS-предел координат: 40 бит, запас 8, H ≥ 1080; float32 — 23 бита. Глубокие исходные сцены показывать обзором, не меняя ссылку/историю; принять обзор можно явно одним действием.
- Binary64 и её самопроверка — только точный PNG, лениво. Отдельный N 64–16384 и исходная камера, временные ресурсы и один кэш. Быстрый PNG захватывает завершённое поле без новых орбит; в economy выбран по умолчанию.
- Очередь ≤ 2, бюджеты DS — 3 мс, binary64 — 6 мс. Общий жизненный цикл fence — `rendering/gpuFence.ts`: timeout=0, безопасный drain, проверки живого поколения и освобождения. Не возвращать активное ожидание или бесконечный повтор ошибочного запроса.
- Выход, сходимость, исчерпание итераций, особенность, численная ошибка и неизвестное покрытие — разные исходы. Неизвестное покрытие (alpha=254) не выдавать за внутреннюю область множества.
- Legacy-формулы сохраняют исходный порядок C-проекта, CPU-эталон независим от GPU-генераторов. Не объединять их ради DRY. Остановленные эксперименты не включать автоматически.
- Compute-query заканчивается до color-pass. Каждый GPU sample учитывается один раз; disjoint/чужие/устаревшие отбрасываются. CPU/fence/подготовку не называть GPU-временем, перепроекции — новыми полями.

## Интерфейс и проверка

- Русские подписи «Параметры», «Оформление», «Скрыть/Показать интерфейс»; меню визуально только `…`, доступное имя «Ещё». Минимальный режим не включает fullscreen, нижняя навигация остаётся.
- От 1280 px панели независимы, ниже открыта одна; ниже 768 px навигация двухстрочная. Поддерживать 320 px, touch, focus/aria, reduced-motion. Blur только у внешних стеклянных поверхностей.
- Тесты/сборки/аппаратные прогоны поручать **GPT-6 Luna**; сложные арифметические расхождения допустимо передать GPT-6.1 Sol. При недоступности модели сообщать, не подменять молча. GPU-прогоны только последовательно.
- Команды: `npm test`, `npm run build`, `npm run test:browser`, `npm run test:browser:all`. Production-check требует свободный порт 4173. Детали и установка браузеров — в руководстве разработчика.
- Новые логи, решения, трассы и измерения — только `.local/`; не перезаписывать прежние результаты. Общий runArtifacts принимает новый/пустой каталог; дочерние инструменты разделяют его только с наследуемым маркером владельца. Публичные иллюстрации — `docs/images/`, без неподтверждённых badges/обещаний.
- Отличать функциональные тесты от аппаратной приёмки: стандартная цель — 60 новых полей/с и p95 ≤ 20 мс, economy — 30 полей/с и p95 ≤ 40 мс. RTX 3060 — контрольный GPU, не приёмка устройства в 2–3 раза слабее. Реальный Android и Safari требуют отдельных запусков; эмуляция их не заменяет.
- Пользовательские данные/формулы/арифметику не менять ради прохождения измерений. Документировать непроверенное и неуспешные измерения. `.git` может отсутствовать — не инициализировать и не переписывать историю без запроса.
